# 本地 Git 批量提交使用说明

日期：2026-10-12。

## 用途与范围

`tools/batch_local_commits.py` 使用已整理的 [候选文件清单](2026-10-12-未提交修改文件清单.json)，将历史累计修改和本次追加按整文件分组，生成三个中文本地提交。详细内容见 [待提交记录](2026-10-12-未提交修改与中文Git批量提交清单.md)。不能从未提交工作树恢复每次编辑的精确历史，也不按代码片段重建历史提交。

需要 Python 3 和 Git，无需 Go/Java 编译环境。脚本不运行压测、不部署、不迁移数据库、不推送远端，也不改写已有提交。

## 操作命令

进入仓库，先执行只读预览：

```bash
cd /data/shizy/wvp-GB28181-pro
python3 -B tools/batch_local_commits.py
```

预览输出每组的中文标题、文件数、逐文件状态/路径，以及计划指纹。默认不执行 `git add` 或 `git commit`。请先检查实际差异，特别是新增文件、部署说明和 SQL；路径排除不是对任意源码/文档内容的自动凭据审计。

确认后执行三个本地提交：

```bash
python3 -B tools/batch_local_commits.py --execute
```

如果希望严格要求与刚审核的内容一致，复制预览输出的指纹执行：

```bash
python3 -B tools/batch_local_commits.py --execute --expect-plan <预览输出的64位指纹>
```

`<预览输出的64位指纹>` 是占位符，运行前替换成实际值。文件内容、权限、HEAD 或计划变化都会使指纹不匹配，要求重新预览。指纹不会证明代码正确或检测所有秘密。

完成后检查真实本地提交记录：

```bash
git log -3 --format='%h %ad %s' --date=iso-strict
git status --short
```

脚本每提交一组立即输出真实完整 commit hash。待提交清单仍是提交前的快照，不会在执行时自动改写成已提交历史。

## 安全检查

- 仅对清单中三个已知分组的文件使用精确字面路径；支持修改、新增和删除，不使用 `git add .`、通配符暂存或强制添加忽略文件。
- 排除 `t.cap`、本地 `tools/application-dev.yml`、压测 `configs/test-10.yaml`、`*.private.*`、抓包/密钥/备份文件，以及根目录或压测工具的 `bin/media/reports`、任意 `target/__pycache__/node_modules` 目录；Java 源码中的 `media` 包不被误排除。排除项保留在工作树，不读取其内容、不暂存。候选文件和清单路径拒绝符号链接。
- 暂存区必须为空；有冲突、merge/rebase/cherry-pick 等未结束操作、索引锁、Git 路径覆盖变量或仓库外元数据时停止。不会替用户取消暂存。
- 当前 HEAD 必须匹配清单基线，候选状态必须与快照一致；清单外非排除项改动、未知分组、重复路径或不符合目录边界的候选文件会阻止执行。
- 提交前校验差异格式、暂存文件集合、暂存对象和文件快照；已跟踪文件先检查 `diff --check`，新增文件在暂存后再检查。提交后校验实际树、父提交和标题，防止 hook/并发操作改变结果后仍继续下一组。
- 保留已有 Git hook、签名和作者配置，不绕过项目检查。脚本不回显可能含源码或凭据的 Git/hook 错误输出；失败时提供操作名和退出码，详细原因需人工检查。

执行期间不要在另一终端编辑候选文件、暂存、提交、切分支或运行会修改源码的格式化工具。脚本有变化检测，但不提供跨进程事务锁；三组不是一个原子事务，后组失败不会撤销前组。

## 失败与续跑

如果第一组已成功、第二组提交失败，第一组保留，第二组可能仍在暂存区。先执行 `git status --short`，人工检查 hook/签名/作者等失败原因和暂存差异。脚本不会自动 reset 或恢复文件。

暂存区仍有内容时不能续跑。可在核对后人工完成该组提交（保持原中文标题和文件集合），或只取消该组的暂存、保留工作树编辑；完成处理后使用：

```bash
python3 -B tools/batch_local_commits.py --resume
python3 -B tools/batch_local_commits.py --resume --execute
```

续跑验证清单基线到 HEAD 之间恰好是计划的前序组，逐项核对单父连续关系、中文标题和提交文件集合。只要存在无关提交、缺漏/多余文件或已提交组的新编辑就停止。该验证不证明历史提交内容与旧预览完全相同，恢复前仍需人工审核已有提交。三组都完成时 `--resume` 仅报告没有剩余提交。

清单过期或新增了其他源码时，不要用宽泛暂存绕过。先人工检查并更新 JSON 清单，保留三组边界和正确基线，再重新预览。已有前序提交时不要把基线随意更新成当前 HEAD。

## 脚本回归验证

```bash
python3 -B tools/test_batch_local_commits.py -v
```

测试仅在本仓库 `target/batch-commit-tests/` 下创建独立临时 Git 仓库，并在这些夹具仓库内验证提交、删除、保护路径、状态/指纹变化、失败保留及续跑。不会提交或暂存 WVP 主仓库。2026-10-12 本次验证 18 项通过；主仓库仅运行预览，HEAD 和暂存区保持不变。

此脚本不引入需要真实环境集成测试的业务变化。本地 Git 夹具回归不替代 WVP/压测工具的业务测试和部署验收，已有真实环境测试及风险继续以 `docs/` 中的实施、复验和阶梯测试文档为准。
