# 压测工具标准国标设备编号实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让压测工具默认生成符合 GB28181 的 20 位纯数字设备/通道 ID，同时保留 `loadtest-` 旧编号兼容模式。

**Architecture:** 配置层新增 `identity` 配置并负责模式、编号段和容量校验；设备层增加带配置的 `IdentityFactory`，数字模式按“前 14 位固定前缀 + 后 6 位序号窗口”生成设备和通道 ID。主程序只映射配置，SIP、RTP、HTTP 点播继续复用现有 `Identity` 字段。

**Tech Stack:** Go 1.22、YAML v3、Go testing。

## Global Constraints

- 只修改 `/data/shizy/wvp-GB28181-pro` 内项目文件。
- 不修改、删除或提交 `t.cap`。
- Git 提交信息使用中文。
- 数字模式设备 ID 和通道 ID 必须是 20 位 ASCII 数字。
- 数字模式使用 Base 最后 6 位序号窗口，首个设备使用 `baseSequence + 1`。
- 旧配置只包含 `idPrefix: loadtest-` 时必须继续使用 legacy 模式。
- 真实 WVP 集成测试只记录风险，不依赖本地单元测试。

### Task 2: 实现数字 IdentityFactory

**Files:**
- Modify: `tools/gb28181-load-test/internal/device/identity.go`
- Test: `tools/gb28181-load-test/internal/device/identity_test.go`

**Interfaces:** 新增 `device.IdentityFactoryConfig{Mode, DeviceBase, ChannelBase, LegacyPrefix, RunID, Domain}` 和 `NewIdentityFactoryWithConfig`；保留旧 `NewIdentityFactory(runID, prefix, domain)` 作为 legacy wrapper。

- [ ] **Step 1: Write failing tests**

增加 numeric 工厂测试：Base 为 `34020000001110000000`/`34020000001310000000` 时 index 0 生成 `34020000001110000001`/`34020000001310000001`，index 1 递增；所有设备/通道 ID 匹配 `^[0-9]{20}$`；Base 序号为 `999999` 时构造失败并包含 `range`。

- [ ] **Step 2: Verify RED**

运行 `cd tools/gb28181-load-test && go test ./internal/device -run 'TestIdentityFactoryNumeric' -count=1`，预期因新构造器不存在而失败。

- [ ] **Step 3: Implement minimal factory**

在工厂中保存设备/通道的 14 位前缀和 6 位起始序号。构造器校验 mode、Base 和序号容量；`New(index)` 计算 `baseSequence + index + 1`，格式化为 6 位并拼接，随后生成 stream、Call-ID 和唯一 SSRC。数字编号耗尽时返回 `numeric identity range exhausted`。设备 ID、通道 ID、SSRC 分别使用唯一集合，重复返回错误。旧构造器调用新构造器并固定 `Mode: legacy`。
