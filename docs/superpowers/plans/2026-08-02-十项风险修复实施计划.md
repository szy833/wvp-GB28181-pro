# 十项风险修复实施计划

> **For agentic workers:** 本计划在当前会话内按阶段执行；每个阶段先增加失败测试，再实现最小修复并运行针对性测试。

**目标：** 按安全、业务正确性、节点隔离和 Redis 资源治理优先级，修复已确认的风险并保留 1-3 项已有修复的回归覆盖。

**架构：** XML 解析统一使用安全工厂；录像查询在发送命令前注册容量为 1 的缓冲队列，避免结束事件先到丢失；媒体离开仅由 `PlayServiceImpl` 作为业务清理监听器处理；Hook 强制按媒体节点隔离；Redis 批量扫描和带 TTL 的临时 key 负责异常兜底。

**技术栈：** Java 21、Spring、MyBatis、RedisTemplate、Dom4j、JUnit 5、Mockito。

## 全局约束

- 只修改 `/data/shizy/wvp-GB28181-pro` 内项目文件。
- 不修改、删除或提交 `t.cap`。
- Git 提交信息使用中文。
- 不改变已修复的下载 TTL、ZLM 参数顺序和 SSRC 耗尽业务错误语义。

### 阶段一：XML 与认证安全

**文件：** `XmlUtil.java`、`SIPRequestProcessorParent.java`、`DigestServerAuthenticationHelper.java` 及对应测试。

- 先增加 XXE、DOCTYPE、超大 XML 和敏感日志测试并确认失败。
- 增加统一安全 SAXReader 工厂，关闭外部实体和 DTD，限制输入大小。
- 删除原始 XML、A1、HA1 等敏感日志。
- 运行 XML 和 Digest 测试。

### 阶段二：录像结束事件

**文件：** `DeviceChannelServiceImpl.java`、录像事件测试。

- 先增加事件先到、事件先于等待、超时和重复 SN 测试。
- 用容量为 1 的 `LinkedBlockingQueue<RecordInfo>` 在发送命令前注册订阅，允许结束事件先到时暂存结果。
- 失败、超时和成功路径统一清理订阅。

### 阶段三：媒体离开清理

**文件：** `InviteStreamServiceImpl.java`、`PlayServiceImpl.java` 及测试。

- 先增加重复离开事件和 InviteInfo 被提前删除的失败测试。
- 移除 `InviteStreamServiceImpl` 对媒体离开事件的独立监听，将 InviteInfo、BYE、播放状态和 RTP 资源清理收敛到 `PlayServiceImpl` 的单一监听器。
- 其他监听器不再并行执行同一业务清理。

### 阶段四：Hook 节点隔离

**文件：** `HookSubscribe.java`、`ZLMMediaNodeServerService.java`、Hook 调用方及测试。

- 先增加同 app/stream 不同媒体节点的隔离测试。
- 修正 `getServerId()` 与媒体节点 `getId()` 混用。
- 普通订阅必须带 mediaServerId；全局订阅显式标记，移除隐式无节点回退。

### 阶段五：Redis 扫描与 TTL

**文件：** `RedisCatchStorageImpl.java`、相关常量/配置及测试。

- 先增加禁止调用 `keys()`、分批删除和临时 key TTL 测试。
- 用 HSCAN/SCAN 和批量删除替换 `KEYS`。
- 为流元数据、Push List、等待 RTP 和流权限增加生命周期 TTL 与异常兜底清理。
- 运行 Redis 单元测试和可用的集成测试。

### 阶段六：验证与提交

- 运行针对性 Maven 测试，再运行可执行的完整测试集。
- 执行 `git diff --check`、`git status --short`，确认 `t.cap` 未变化。
- 使用中文提交信息提交全部本次修改。

## 集成验证风险

- 本次 Redis `SCAN/HSCAN`、TTL 和多媒体节点 Hook 隔离仍需要真实 Redis/ZLM 环境验证，重点覆盖 Redis Cluster 游标、旧版共享 Hash 迁移、节点重启和同名流并存场景。
- 当前 Maven 全量编译受仓库既有 `RedisUtil2.java:900` 编码/路径异常阻塞；本次改动已使用定向 `javac` 和 JUnit Launcher 完成回归验证，但未替代真实环境集成测试。
