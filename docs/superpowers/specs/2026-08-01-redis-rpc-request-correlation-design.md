# Redis RPC 请求关联与超时清理设计

## 目标

修复 Redis RPC 的 `sn` 碰撞、同步订阅注册竞态、响应串包和异步 callback 长期驻留问题。当前集群只运行同一版本的 WVP，保留现有 `long sn` 协议，不需要兼容旧版本行为。

## 设计

### 请求标识

使用 JVM 内的 `AtomicLong` 生成单调递增的 64 位 `sn`，不再使用 `1..1000` 的随机数。序号从较大的随机起点开始，降低与未升级外部实例的重叠概率；实际响应关联仍以当前请求实例为准。

### 待处理请求

同步队列和异步 callback 统一登记为一个待处理请求对象，Map 注册使用 `putIfAbsent`，清理使用带 value 的 `remove`。对象记录请求类型、队列或 callback 以及过期时间，避免一个请求误删或覆盖另一个请求。

### 响应路由

响应先校验 `fromId` 是否等于当前 WVP 的 `serverId`，再原子移除对应待处理请求并投递结果。迟到响应、重复响应和其他节点的响应不再影响本地请求。

### 超时与中断

同步请求在 `poll` 返回 `null` 时返回统一超时结果，并在 `finally` 中只清理自己的待处理对象；线程中断时恢复中断标志。异步请求增加带 TTL 的接口，并在 `user-settings.redis-rpc-callback-ttl` 中提供默认 TTL（默认 30 秒）；过期后自动移除并执行一次超时 callback。无论 callback 是否抛异常，状态都先完成清理。

## 验证

增加单元测试覆盖：唯一序号、重复注册、同步/异步隔离、响应来源校验、同步超时、异步 TTL 清理、迟到响应以及 callback 异常后的清理。

## 非目标

- 不修改 Redis RPC 消息结构和 `sn` 字段类型。
- 不修改 ZLM、GB28181 SIP 或媒体节点相关逻辑。
- 不处理不同版本 WVP 节点混跑场景。
