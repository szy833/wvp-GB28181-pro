# 压测完整结果输出设计

## 目标

让一次 GB28181 压测可以完整看到注册、目录、点播、媒体确认、停止清理和错误原因，并同时满足实时观察与后续离线分析。

## 输出层次

1. 控制台摘要：运行结束时输出设备数、阶段成功率、点播成功率、媒体确认数、停止清理数和延迟分位数。
2. JSON 报告：保存脱敏后的运行配置、阶段汇总、计数器/直方图、每台设备结果和每次点播结果。
3. CSV 报告：保留现有阶段汇总 CSV，并额外生成明细 CSV；每行标识设备或点播记录，便于 Excel 和脚本分析。
4. Prometheus：继续保留实时指标，并补充注册、目录、INVITE、媒体和停止阶段计数。

## 数据模型

- `Stage` 增加成功率、耗时和延迟分位数。
- `DeviceResult` 记录设备编号、通道编号、注册/目录结果和错误原因。
- `PlayResult` 记录一次点播的开始、停止、成功状态、耗时和错误原因。
- `ReportConfig` 增加可选 `detailCsv`；为空时根据现有 `report.csv` 自动生成 `<name>.details.csv`。
- JSON 中不保存 SIP 密码、控制 token 或完整 URL 查询参数。

## 采集边界

- 设备层记录 REGISTER 挑战/成功、Catalog 响应、INVITE 200、媒体启动和设备 BYE。
- 调度层记录每次 HTTP 点播开始/停止及其错误。
- 现有计数器继续作为 Prometheus 数据源；报告在运行结束时从同一注册表快照生成。
- 并发写入只通过线程安全收集器完成，设备关闭后再生成报告。

## 兼容性与验收

- 现有 `report.json` 和 `report.csv` 路径继续有效。
- 未配置 `detailCsv` 时不改变现有配置即可获得明细文件。
- 单元测试覆盖报告 JSON、阶段/设备/点播 CSV、摘要输出和并发点播记录。
- 本地集成测试应能从报告中看到注册、Catalog、点播成功、媒体确认和停止清理结果。
