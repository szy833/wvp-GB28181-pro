# REGISTER 续订轻量路径设计

## 目标

避免同一 `Call-ID` 的 REGISTER 续订重复执行完整设备上线流程，降低设备集中续订时的数据库和 Redis 峰值，同时保留离线恢复和注册信息变化的正确性。

## 路径划分

| 场景 | 处理方式 |
| --- | --- |
| 首次 REGISTER | 保持完整 `online()`，创建设备、同步通道和建立订阅 |
| 同一 `Call-ID` 且缓存设备在线 | 调用 `onlineRenewal()`，只刷新设备过期状态 |
| 同一 `Call-ID` 但缓存设备离线 | 回退完整 `online()`，恢复原有上线流程 |
| 续订中的 IP、端口、协议或 Expires 变化 | 轻量路径额外更新数据库和 Redis 设备缓存 |

## 实现细节

REGISTER 处理器在修改设备字段前比较旧值，记录注册信息是否变化。`onlineRenewal()` 不查询 Redis、数据库或设备通道；信息未变化时只刷新 `DeviceStatusManager` 的过期时间。注册时间列表仍由处理器单独写入 Redis，用于保留现有注册记录能力。

当注册网络信息发生变化时，轻量路径更新 `update_time`、在线状态、数据库设备记录和 Redis 设备缓存。这样后续设备控制仍使用最新的网络地址，同时不会为每次固定周期续订重复执行完整持久化。

## 验证

- 未变化续订不调用设备数据库更新或 Redis 设备更新。
- 注册信息变化时调用数据库和 Redis 更新。
- 设备状态过期时间在两种续订情况下都会刷新。
- 缓存设备离线时继续使用原有完整 `online()` 流程。
