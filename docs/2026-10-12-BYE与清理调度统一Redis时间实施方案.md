# BYE 与清理调度统一 Redis 时间实施方案

## 范围与约束

仅统一 BYE 首次/最近尝试、重发资格、本地终止及 Invite 清理 PENDING 的写入、认领、续租、退避和到期扫描。注册、GPS、录像时间、媒体时间轴以及 Invite 的其他业务期限不改动。进程执行预算继续使用 `System.nanoTime()`。

Redis 时间是共享墙上时钟，不是单调时钟；Redis 主备仍需正常同步时间，禁止将本方案宣传为任意时钟跳变下的严格 32 秒保证。不得改共享机器时钟、重启服务或修改现场 Redis/SQL 来制造通过。

## 实现计划

1. 先补失败回归：首次 BYE 必须声明 REDIS 时间来源，紧接着的第二次尝试不能获得发送资格。
2. Lua 在已有 CAS 和清理 lease 校验下授予发送资格，用同一次 Redis TIME 建立首次/最近时间；首时间只建立一次，10 秒重发限制由 Lua 执行。设备和平台均改用该入口。
3. 本地终止仅由 Lua 判断 Redis 时间已到、同代 RTP/STATE 完成、SIP 已接受且未确认结束；终止时间也由 Redis 生成。保留真实响应、主动 BYE 与本地超时的事实区别。
4. 增加 BYE 时间来源和操作标识。Lua 生成的字段不再以 Java 预期 JSON 完全相等确认结果；按操作标识及持久化事实读回确认，未知提交不授权后续 SIP 副作用。避免重新编码整个 JSON 改坏媒体数组或字段精度。
5. PENDING 的登记、claim、completeStep 续租、defer 和读取全部使用 Redis TIME。退避在 RTP/STATE 已确认关闭时不越过剩余 BYE 等待窗口，窗口已过则短退避；其他失败仍保留原退避策略。
6. 执行定向与全量隔离 Java/真实 Redis 回归，覆盖 JVM 时间领先/落后、仓库重建、并发尝试、响应丢失、错误 lease、旧时间来源、旧代事件、正常 BYE 和真实等待窗口。
7. 更新操作文档、运行 git 状态和差异检查；无提交要求则不提交。由用户部署后再做共享 WVP/ZLM 端到端复验，不能将源码测试写成运行实例已修复。

## 部署边界

不支持新旧版本混跑。部署前核验并排空活动 Invite、STOPPING 和 PENDING，然后切换新版本。历史 CLOSED 摘要原样保留，不把旧 JVM 时间换算成 Redis 时间。遇到已有首次时间但无 REDIS 来源的活动记录，新逻辑拒绝猜测该时间；需要完成旧版本排空，而不是清空数据库或强制释放 owner。

## 真实环境集中验收

用户部署后，用相同 10 台模拟设备验证：正常播放与停止、旧代停止不影响新代、SIGKILL 模拟器后自动回收、同编号重注册与重播。分别记录首次 BYE 到本地终止、退出到资源归零及归零后 70 秒稳定观察。现有 Redis/WVP 约 80.56 秒偏差可用于检验跨主机时钟独立性，但不改变机器时钟。

最终必须核对 Invite/owner/job/lease/PENDING、SIP V2、SQL 代次、SSRC 预留和 ZLM media/listener。32 秒是 BYE 等待窗口，不是包含外部依赖故障的总清理 SLA。共享依赖故障、Redis 主备切换与真实摄像头断网恢复需隔离条件另行集中执行。

## 源码实现

- `InviteInfo` 新增 `byeClockSource` 和 `byeOperationId`，分别标明时间来源及一次原子操作身份。历史 CLOSED 摘要不回填这些字段。
- `InviteRepository.beginByeAttempt(inviteId, lease)` 替代原 `byeSent(inviteId)`。Lua 在原始字节 CAS、STOPPING、SIP 接受/最终响应、匹配 Dialog、非跳过/非确认、正确 lease 下检查 10 秒重发间隔，再以一次 Redis TIME 写入首次和最近尝试时间。首次时间只建立一次。
- `terminateByeLocally()` 不再使用 JVM 时间预判；Lua 同时核验 Redis 时间到期、RTP/STATE 已完成及资源非创建中，并原子写终止时间和 BYE 步骤。真实对端确认与本地终止依旧分开记录。
- Lua 仅替换 Java 生成的唯一数值占位字段，不用 cjson 重编码整条 Invite。Java 按操作身份和已持久化的正时间戳读回确认；提交异常但读回能确认时返回 ALREADY_APPLIED，不能确认就失败，不回退 JVM 时间、不授权 SIP 发送。
- `PlayServiceImpl` 的设备和平台发送分支都携带当前清理 lease 获取授权。平台分支补充 Dialog 的 Call-ID 一致性检查。读回若已经确认或跳过停止，则不再发送多余 BYE。
- STOP/LATE/RESOURCE 登记 PENDING、claim、completeStep 续租、defer 和有上限到期扫描均使用 Redis TIME。续租同时延后待办 score，防止 lease 已续期而待办 score 提前到期。
- defer 保留指数退避和抖动；只有 RTP/STATE 已完成且 BYE 时钟合法时，将退避限制在剩余窗口内，到期后最多退避 1 秒。外部资源仍未确认时维持原退避，不将未知媒体/SQL 状态视为已清理。

## 性能与失败边界

TIME 在已有 Lua 调用内执行，不为每次判断增加独立网络往返。成功的 BYE 时间戳写入需要读回原记录确认，增加一次 GET；PENDING 扫描仍每轮最多 200 条，编排最多取 100 条并使用单调时间检查 500ms 执行预算。没有新增全量扫描、全局锁或每会话调度线程。

Redis 不可用、提交未知、lease 失效时不发送未经确认的 BYE，也不释放无法确认的资源。恢复后依靠持久待办和 lease 到期重试。本方案不承诺外部 SIP 副作用恰好一次，也不承诺依赖故障、工作线程停顿或 Redis 时钟跳变期间的严格墙上时间 SLA。

## 部署与回退操作

本次无 SQL 结构迁移、无配置项变更。切换前必须只读核验旧版本活动 Invite、STOPPING 和 PENDING 已排空；有旧首次/最近 BYE 时间但无 REDIS 标记的活动记录会拒绝发送授权/本地超时终止，不能靠删除记录或换算主机偏差绕过检查。回退旧版本同样先排空新版本活动会话，不能将 Redis 时间记录直接交给按 JVM 时间比较的旧代码。

用户负责构建部署；本轮源码验证不替换运行中的 class、不重新启动共享 WVP/ZLM、不写共享 Redis/SQL、不调整机器时钟。部署后按本文件的集中验收清单继续验证，不用隔离测试结论替代端到端验收。

## 隔离验证

编译输出和依赖缓存位于仓库内独立目录，未覆盖运行中的根 `target/classes`。Testcontainers 启动独立 Redis 7.4 容器，未连接共享业务 Redis。编排测试的 SQL/RTP 适配器使用 mock，不将其结果称为真实媒体回收完成。

```bash
LC_ALL=en_US.utf8 TESTCONTAINERS_RYUK_DISABLED=true mvn -o \
  -f target/invite-lifecycle-check/pom.xml \
  -Dmaven.repo.local=/data/shizy/wvp-GB28181-pro/target/invite-lifecycle-check/maven-repository \
  -Dgit.skip=true -DskipTests=false test
```

回归覆盖：

1. 首次操作记录 REDIS 来源和操作身份，紧邻第二次尝试被拒绝；仓库重建和允许重发后首次时间不变。
2. 仓库应用时钟参数分别领先/落后两分钟，STOP 待办、首次/最近尝试、本地终止均落在 Redis TIME 的前后取样区间；窗口未到不能终止。此项通过测试时钟入口模拟偏差，没有改机器时钟。
3. 八线程同一会话并发仅获得一份发送许可；错误 lease 不能开始 BYE、续租或退避另一个工作者的任务。
4. 首次尝试/本地终止提交后的响应丢失可按操作身份确认；写入未发生时不能授权，也不能建立假时间戳。
5. 未知旧时间来源拒绝猜测转换；真实 ACK 和设备主动 BYE 不被误记为本地超时；迟到首次 200 OK 重开窗口，重复 200 OK 不刷新起点。
6. claim、续租、defer 和到期扫描保持同域；未到期任务不提前扫描；已确认资源的退避不越过剩余窗口，未知资源维持原退避。
7. 真正等待一次 32 秒窗口及 30 秒 lease 自然过期，再由新工作者收尾；十轮真实 Redis 主记录/待办/SIP 索引闭环与同通道重播不误伤新 owner。
8. 嵌套媒体的超出 Lua 双精度整数安全范围的 Long 和带转义时间戳文本保持原值；连续编排不重复发 BYE，平台发送也必须获得仓库授权且 Call-ID 匹配。
