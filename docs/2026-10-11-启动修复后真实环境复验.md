# 启动修复后真实环境复验

## 计划与风险边界

用户通知服务重启并授权再次测试。先核验新构建、在线媒体节点与资源基线，再进行 1 路和 10 路测试。上一阶段失败则不扩大并发。

实际环境：WVP HTTP `127.0.0.1:18080`，SIP `192.168.7.9:5060`，ZLM HTTP `127.0.0.1:19001`；Redis `192.168.7.5:6379` DB 7；MariaDB `192.168.7.5:3306/wvp`。

步骤：

1. 只读检查版本、服务端口、Invite/SIP/待办、媒体与 listener。已观察构建时间 `2026-10-11T21:38:10+08:00`，WVP PID 1943，所有活动资源为零，磁盘剩余约 12.46 GiB。
2. 使用全新模拟设备编号注册并查询目录；设置测试设备收流模式为 TCP-PASSIVE。
3. 同批并发点播，验证实际 `gb_…` 流、SIP 会话、ACTIVE 主记录、四项确认事实与 SQL owner/epoch 投影；单路增加重复点播共享 owner 检查。
4. 实际建立观看连接并抽样 FFmpeg 解码；按 start 返回的实际 stream 停止，并重复停止。
5. 保持模拟设备在线继续检查清理，随后重新点播；发送上一代 stream 的迟到停止，确认不能关闭新代。
6. 再次停止并观察；并发阶段额外用第三轮点播验证模拟设备集中 BYE 后的清理。
7. 结束模拟设备并最终复核。CLOSED 摘要与带期限的 Call-ID 索引按设计保留，不算活动残留；必须检查 owner、ACTIVE、PENDING、JOB/LEASE、SSRC 预留、SIP、媒体、listener 和 SQL stream/state。
8. 若前两阶段通过，再补 1 路不建立观看连接，等待无人观看自动关闭并检查完整清理；随后验证同设备可再次点播。

旧候选二进制仅作为已验证的 SIP/媒体模拟器使用，禁用其自动 HTTP 点播；独立验收脚本负责新协议的实际流名、按代停止及结果判定，不沿用旧报告对流名的假设。

仅测试本轮模拟设备。不重启/部署服务，不执行 SQL/Redis 人工修复、数据删除或故障注入，不操作真实摄像头。数据库仅 SELECT，Redis 仅读命令，正常注册/点播/停止产生的业务写入除外。认证信息不输出到报告，动态模拟器配置设为 0600 并排除 Git。

磁盘低于 4 GiB、内存可用低于 1 GiB、发现播放/清理异常时停止扩大并发；自有模拟器、观看、解码及采集进程在退出路径收尾。模拟设备/通道记录保留供追溯，不以手工清库使结果归零。

- 首轮两个并发 stop、次轮两个并发 stop 均受理，约 4.06 秒内完整清理；不能将 stop 受理时间误当资源归零时间。
- 再次点播生成不同的 Invite/实际流/resourceId，SQL epoch 从 1 增至 2。发送上一代实际 stream 的 stop 后，新代继续 ACTIVE、可观看。

## 最终独立复核与发现

三阶段均通过后，再建立独立的 Redis/JDBC 只读连接重新核验本轮全部 12 台模拟设备、35 个 Invite 代次，结果为 `passed=true`：

| 项目 | 最终结果 |
|---|---|
| Invite ACTIVE / PENDING / PLAYING | 全部 0 |
| SSRC 持久预留 / RECONCILE 对账成员 | 全部 0 |
| SIP 会话 / SIP 删除补偿待办 | 全部 0 |
| ZLM 媒体条目 / RTP listener | 全部 0 |
| 本轮业务 owner / DEVICE、CHANNEL、STREAM、SSRC 活动索引 | 全部清理 |
| 本轮 JOB / LEASE | 全部清理 |
| SQL 投影 | 12/12 CLOSED、stream=NULL；保留的 seq/epoch/owner 与各通道最后一代一致 |
| 终态摘要及 DUE | 保留 35 条正常 CLOSED 摘要和到期任务，不按活动残留判定 |
| WVP / ZLM | PID 1943 / 13291，与测试前相同；未重启服务 |
| 自有模拟器、观看、解码、采集进程 | 已退出；19103 监控端口已关闭 |
| 磁盘 / 可用内存 | 最终约 12.43 / 9.57 GiB |

最终证据：`tools/gb28181-load-test/reports/invite-lifecycle-20261011-final-verification/final-verification.json`。

合计 36 次 start 请求成功，对应 35 个独立代次；60 次包含重复/旧代保护的 stop 请求受理；集中退出试验 10/10 设备 BYE 成功；10 次抽样解码共 4,560 帧，无解码错误。10 路阶段主机 CPU busy 采样峰值约 31%，不代表容量上限。

本轮没有复现此前的启动循环依赖、再次点播失败、Invite 写入丢失、停止后通道 stream 残留或待办无法收敛。需要区分的正常行为是：stop 返回成功表示受理，完整清理约需 2–5 秒；CLOSED 摘要/Call-ID 索引保留用于迟到事件处理，并非删除失败。

本次仅增加验收脚本、证据和文档，没有修改 WVP 生产源码、执行人工 SQL/Redis 修复、部署或提交 Git。认证配置保持 0600；通过本地 `.git/info/exclude` 排除报告目录下 `*.private.yaml`，不提交凭据。
