## 验收脚本准备

仓库内临时诊断入口 `target/invite-lifecycle-check/redis_clock_live_acceptance.py` 复用现有验收流程，扩展采集 `byeClockSource`、`byeOperationId`、最近 BYE 时间与 Redis TIME。PENDING 逾期统计改为与 Redis 时间比较，避免报告本身再次混用时钟。数据库使用只读 JDBC 连接，凭据从关闭终端回显的 stdin 传入，不写命令参数或报告。

首个入口因私有配置中的数据库凭据与现场不同而在只读数据库连接阶段失败，尚未启动模拟器或发出点播请求。失败日志保留在 `target/invite-lifecycle-check/redis-clock-live-abrupt-20261012.log`，空报告目录保留；改用之前用户提供的现场凭据经 stdin 输入，新建 r2 目录复验，不覆盖原失败证据。

注册就绪判断的 4 项隔离回归通过：旧 SQL 行不等于重新注册成功，REGISTER/Catalog 必须均完成。验收脚本等待本轮成功计数、设备在线和通道存在后才点播。

## 执行步骤

第一组入口：

```bash
python3 target/invite-lifecycle-check/redis_clock_live_acceptance.py \
  ten-redis-clock-abrupt-20261012-r2 \
  --previous-stage ten-offline-bye-replay-20261012 \
  --wvp-pid 17835 --abrupt-exit --credential-stdin
```

该命令需要通过关闭终端回显的 stdin 输入数据库凭据，不能把凭据写入命令参数。步骤依次为：基线核验 → 10 台重新注册/目录就绪 → 10 路点播/观看及首尾解码 → 20 次重复停止 → 归零后 70 秒观察 → 新代重播 → 旧流停止不影响新代 → 再观看/重复停止 → 第三轮播放 → SIGKILL 仅终止本轮模拟器 → 等待本地 BYE 终止与资源归零 → 归零后 70 秒观察。

随后使用相同编号重新注册，重复完整流程但正常 SIGINT 退出；最后用新建只读 Redis/JDBC 连接连续三次跨层终检。每阶段必须通过后再继续，不以兜底停止、删设备、清空缓存制造成功。
