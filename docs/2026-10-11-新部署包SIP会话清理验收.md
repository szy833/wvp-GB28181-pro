### 新发现：InviteInfo 未完全收敛

这不是 V2 `SsrcTransaction` 残留。实际观察到 SIP 会话/媒体流/listener 已归零，但 InviteInfo 仍被定时孤儿清理选中，再报“缓存事务信息未找到”。第三轮设备 `37020000001110708007`（通道数据库 ID 235）有如下完整证据：

| 时间 | 实际 Redis / 日志事件 | 解释 |
|---|---|---|
| 14:51:00.913669 | WATCH 该 Invite 版本键和全局 `VMP_GB_INVITE_INFO` 后，包含 HDEL 的 EXEC 返回 null | InviteInfo 删除事务中止，非 SIP 会话删除 |
| 14:51:01.706233 | 调度路径 HDEL 的 EXEC 返回 8 项结果 | 本次确实删除了 InviteInfo |
| 14:51:01.713 | WVP 报 BYE“缓存事务信息未找到” | SIP 会话已经被正常清掉 |
| 14:51:01.724388 | 同字段 HSET 的 EXEC 返回 7 项结果 | 刚删除的 InviteInfo 又被恢复 |
| 14:51:31.700044—14:51:31.713452 | 下一轮再次 HDEL 成功，继而 HSET 成功 | 形成每 30 秒的删除/恢复循环 |
| 14:51:57.476780 | 同字段 HDEL 成功，此后该观察窗口无恢复 | 与设备离线兜底阶段一致，历史设备记录保留 |

原始脱敏证据在 `fix-retest-invite-observation.redis-wire.jsonl`，该窗口覆盖部分第三轮、并发 API 停止及后续观测，总计有 13 个 Invite 事务 EXEC 中止（不能将这个跨阶段总数全部算到第三轮）。早期诊断脚本把 HGET 的 null 响应也命名为 `NULL_ABORT`；**只有 command=EXEC 且 result=NULL_ABORT 才代表事务中止，HGET null 只是记录不存在**。后续脚本已区分 `NULL_VALUE`。

当前源码对应链路：

- `InviteStreamServiceImpl.watchInviteMutation()` 在索引未激活的兼容模式下会 WATCH 共享主 Hash；这是兼容旧写入方的保护，不能未经迁移核对直接移除。
- `removeInviteInfoIfSame()` 单次条件删除，WATCH 中止返回 false，没有和 SIP 会话删除一样的有限重试；上层 `removeInviteInfo()` 忽略返回结果。
- `PlayServiceImpl.stopIfOwner()` 先删除 InviteInfo，再清理资源；`safeSendBye()` 把 SIP 会话不存在也当失败，最后 `restoreInviteInfoIfAbsent()` 恢复已结束记录。运行观察到的 HDEL/HSET 及调度日志与此链路一致。

第一、二、三轮、并发 API 停止及重复启停均有不同程度的上述定时警告，不能简单当作完全正常的重复日志。当前五阶段点播及再次点播未因此失败，但数据库/Redis 额外工作和业务状态不收敛需要单独修复。建议优先明确当前索引迁移/激活状态、补齐删除重试和结果处理，并将“目标会话已不存在且媒体已关闭”视作幂等停止成功，防止错误恢复；修改后对 InviteInfo 本体及索引增加清理验收。

### 其他观察与性能边界

- 设备集中退出阶段，WVP 因媒体离开与 BYE 交错发出的部分反向 BYE 未观察到 200。工具在自身 BYE 收到 200 后关闭 SIP transport，可能放大此时序；这不等于设备发往 WVP 的 BYE 未确认，也未造成本轮 SIP 残留。三轮纯集中退出未确认的反向 BYE 分别为 5、4、1 个；重复启停最终退出阶段另有 3 个。平台主动并发停止对照为 10/10 响应正常。
