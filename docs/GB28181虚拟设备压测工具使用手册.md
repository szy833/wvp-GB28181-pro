# GB28181 虚拟设备压测工具使用手册

## 1. 工具定位

`tools/gb28181-load-test` 用于在隔离测试环境模拟多台 GB28181 设备，并驱动 WVP 进行注册、目录同步、点播、收流和资源释放测试。

当前支持 UDP SIP、Digest REGISTER、Catalog/DeviceInfo/DeviceStatus 查询响应、UDP RTP/PS、TCP-PASSIVE RTP、共享媒体文件、WVP HTTP 点播调度、Prometheus 指标和 JSON/CSV 报告。

工具只用于测试环境，不应直接连接生产 WVP、Redis、MySQL 或 ZLMediaKit。

## 2. 前置条件

需要准备 Go 1.22 或更高版本、可访问的测试 WVP/ZLMediaKit、一台 WVP 可以访问的压测主机、一份视频文件，以及可选的 WVP JWT。这里的 JWT 是 WVP 用户登录后的 `access-token`，不是 GB28181 设备的 Digest 密码。

确认网络连通性：

```bash
nc -vz <wvp-ip> 5060
nc -vz <wvp-ip> 18080
```

TCP-PASSIVE 模式还要求压测主机能够主动连接 WVP 的 RTP 监听端口。

## 3. 准备媒体文件

```bash
cd /data/shizy/wvp-GB28181-pro/tools/gb28181-load-test
./scripts/prepare-media.sh /path/to/input.mp4 media/sample.ps
```

工具启动时只读取一次 PS 文件，所有虚拟设备共享只读媒体缓冲区，每个播放建立独立读取游标。

脚本使用 FFmpeg 的 `mpeg` muxer 生成 MPEG Program Stream。不要手动改成 `mpegps`，该名称在常见 FFmpeg 版本中不是有效的输出格式；如果原视频不能直接封装，脚本会自动尝试转码为 MPEG-2 视频后再封装。

## 4. 配置文件

```bash
cp configs/example.yaml configs/test-10.yaml
```

关键配置示例：

```yaml
runId: test-20260805-01
sip:
  address: 192.168.3.167:5060
  local: 0.0.0.0:0
  advertise: 192.168.3.172
deviceCount: 10
identity:
  mode: numeric
  deviceBase: "34020000001110000000"
  channelBase: "34020000001310000000"
domain: 3402000000
startRate: 5
registerTtl: 3600s
keepalive: 30s
device:
  username: "{deviceId}"
  password: your-test-password
  realm: 3402000000
  serverId: 34020000002000000001
  name: GB28181 Load Test Device
  manufacturer: gb28181-load-test
  model: virtual-camera
scenario:
  name: steady-play
  duration: 10m
  playRate: 2
  maxConcurrent: 10
  playDuration: 2m
  startupGrace: 30s
control:
  baseUrl: http://127.0.0.1:18080
  # WVP 登录返回的 access-token 值，不要加 Bearer 前缀
  token: your-wvp-jwt
  startPath: /api/play/start/%s/%s
  stopPath: /api/play/stop/%s/%s
metricsAddr: 127.0.0.1:19100
media:
  file: ./media/sample.ps
report:
  json: ./reports/test-10.json
  csv: ./reports/test-10.csv
```

注意事项：

- `sip.advertise` 必须是 WVP 能访问到的地址，不能填 `0.0.0.0`；
- `sip.local: 0.0.0.0:0` 会为每个虚拟设备分配独立端口；
- `identity.mode: numeric` 生成 20 位纯数字的设备和通道 ID，可直接通过 WVP 严格设备 ID 校验；`deviceBase` 与 `channelBase` 必须使用测试专用编号段，不能与生产设备重叠；
- 旧配置可显式使用 `identity.mode: legacy` 和 `idPrefix: loadtest-`，但该模式在 WVP `device-id-strict: true` 时会被拒绝；
- `device.username` 中的 `{deviceId}` 会替换成当前虚拟设备 ID；
- `playRate` 是每秒发起的 WVP 点播请求数，不是视频帧率；
- `maxConcurrent` 限制同时等待 WVP 点播结果的 HTTP 请求数；
- `startupGrace` 应覆盖注册和目录同步时间；
- 不配置 `control.baseUrl` 时，点播需要通过其他方式触发；
- `no-media-timeout` 会返回 INVITE 的 200 OK，但不会发送 RTP。

## 5. WVP 测试环境准备

建议使用独立的 WVP 配置和数据库。启动前确认：

1. SIP 监听地址包含压测主机可访问的网卡；
2. WVP 设备认证密码与 `device.password` 一致；
3. WVP 已连接测试 ZLMediaKit；
4. ZLMediaKit 的 UDP/TCP RTP 端口范围足够大；
5. JWT 具有 `/api/play/start` 和 `/api/play/stop` 权限；
6. 录像目录、Redis 内存和数据库连接池设置了上限和监控。

标准 numeric 模式生成的设备和通道编号符合 WVP 的 20 位纯数字校验，无需关闭 `user-settings.device-id-strict`。只有使用 legacy 模式时才需要非严格校验；不要为了压测直接复用生产设备编号。

### 获取 control.token

WVP 登录接口为 `/api/user/login`。密码按 WVP 约定使用 32 位 MD5 值：

```bash
password_md5=$(printf '%s' '你的密码' | md5sum | awk '{print $1}')
curl -s -X POST \
  "http://127.0.0.1:18080/api/user/login?username=admin&password=${password_md5}"
```

登录响应中的 `accessToken`，或响应头中的 `access-token`，就是配置文件里的 `control.token`。压测工具会把它作为 `access-token: <token>` 请求头发送，不要填写 `Bearer <token>`。

## 6. 构建和运行

```bash
go mod tidy
go test ./...
go test -race ./...
go run ./cmd/gb28181-load-test -config configs/test-10.yaml
```

也可以构建二进制：

```bash
go build -o bin/gb28181-load-test ./cmd/gb28181-load-test
./bin/gb28181-load-test -config configs/test-10.yaml
```

压测机不需要安装 Go。将构建机生成的二进制、配置文件和 `media` 目录复制到压测机后，直接运行：

```bash
GB28181_LOADTEST_INTEGRATION=1 ./scripts/run-integration.sh configs/test-10.yaml
```

脚本会优先执行 `./bin/gb28181-load-test`；如果二进制不在默认位置，可以指定：

```bash
GB28181_LOADTEST_INTEGRATION=1 \
GB28181_LOADTEST_BIN=/opt/gb28181-load-test \
./scripts/run-integration.sh /opt/gb28181-load-test/test.yaml
```

如果配置中的媒体文件和报告路径使用相对路径，建议从工具目录启动，或改为绝对路径。

集成脚本有显式保护：

```bash
GB28181_LOADTEST_INTEGRATION=1 ./scripts/run-integration.sh configs/test-10.yaml
```

## 7. 推荐压测阶梯

| 阶段 | 设备数 | 点播速率 | 目的 |
| --- | ---: | ---: | --- |
| 基线 | 10 | 1-2 路/秒 | 验证注册、目录和点播闭环 |
| 小规模 | 100 | 10 路/秒 | 验证线程池、Redis 和 RTP 端口增长 |
| 目标规模 | 1,000 | 50-200 路/秒 | 观察稳定运行和资源上限 |
| churn | 100-1,000 | 周期启停 | 观察 InviteInfo、RTP、SIP 会话清理 |
| 超时 | 10-100 | 按需 | 使用 `no-media-timeout` 验证收流超时 |
| 主动退出 | 10-100 | 按需 | 使用 `device-bye` 验证 BYE 清理 |

每个阶段至少保存配置、JSON/CSV 报告、WVP/ZLM 日志、Redis 内存、MySQL 连接池、JVM CPU/堆和网络监控快照。

## 8. 指标和报告

配置 `metricsAddr` 后访问：

```bash
curl http://127.0.0.1:19100/metrics
```

常用指标：

- `devices_started_total`：已启动虚拟设备数；
- `play_requests_total`：发起的 WVP 点播请求数；
- `play_start_errors_total`：WVP 点播失败数；
- `play_stop_errors_total`：WVP 停止点播失败数；
- `wvp_control_latency_seconds_count`、`_sum`、`_max`：WVP HTTP 调用次数、总耗时和最大耗时。

进程收到退出信号后才会执行统一清理并写入 JSON/CSV 报告。

## 9. 常见问题

### REGISTER 收到 401 后仍不上线

检查 `device.password`、`device.username` 和 SIP 域；numeric 模式应确认 WVP 收到 20 位数字设备 ID，legacy 模式还要确认 WVP 是否关闭了严格设备 ID 校验。

### WVP 找不到设备或通道

检查 `sip.advertise`、REGISTER Contact、Catalog 查询响应和 WVP 是否已完成目录同步。

### HTTP 点播返回 404 或设备不存在

增加 `startupGrace`，确认 WVP 数据库中存在设备和通道，检查 `control.startPath` 及 JWT。

### INVITE 成功但没有媒体

检查 WVP SDP 的地址、端口和 `a=setup`，确认 RTP 端口可达、PS 文件可读取，并对照 WVP RTP 首包和 ZLMediaKit Hook 日志。

### 运行一段时间后内存或端口耗尽

降低 `startRate`、`playRate` 和 `maxConcurrent`，检查 BYE/停止接口、ZLMediaKit 残留流、操作系统 UDP 临时端口和文件描述符限制。

## 10. 清理和安全

- 只在测试网开放 SIP、RTP 和 HTTP 端口；
- 不把生产 JWT、设备密码写入 Git；
- 测试结束后确认没有残留流、InviteInfo、SIP 会话和录像文件；
- 真实环境结果应保存到测试报告，不要将生产日志复制到压测项目。

真实环境风险详见 `docs/GB28181虚拟设备压测集成测试风险.md`。
