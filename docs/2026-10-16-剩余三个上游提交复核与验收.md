## 无人观看与停止链路

当前 `PlayServiceImpl.onApplicationEvent(MediaDepartureEvent)` 按媒体节点及代次业务流查询 Invite，媒体不存在时调用 `stop(inviteInfo)`，进入持久化清理流程。不会使用旧代码的“先删除 Invite，再尝试发送 BYE”顺序。

本轮除现有测试外，用实际 PlayServiceImpl 事件入口与既有清理夹具增加临时探针，验证：

1. 已接受 SIP 的 ACTIVE Invite 在媒体离开后发送 BYE，关闭 RTP/STATE，保留 STOPPING 与 Dialog 等待确认。
2. 立即重复媒体离开不再次发送 BYE；模拟对端确认后收敛为 CLOSED。
3. 没有 originUrl 且媒体探测为存在或未知时，不发送 BYE、不关闭资源。
4. 旧代业务流没有对应 Invite 时，不影响新代 Invite。

这里直接调用 Java 事件方法，SIP 发送、媒体节点和清理存储为测试夹具；不是对真实 ZLM Hook 调度或 SIP 网络重传的验证。

## 并发点播链路

- `PlayServiceImpl.startInvite()` 以类型、通道和回放/下载时间段构造 businessSlot，创建者通过 `createInvite()` 认领；其他请求加入当前 owner 的等待者。
- `InviteRepository.createAndClaim()` 的 CREATE 分支在同一 Redis Lua 脚本中检查 owner 并写入记录，不能用进程内回调表替代这个协调机制。
- `InviteStreamServiceImpl.await()/complete()` 按不可变 inviteId 保存结果，处理晚到等待者、重复完成和单个回调抛异常。
- `PlayServiceImplInviteCallbackTest.hundredDuplicateStartsHaveOneResourceAndSipOwner` 验证 100 个请求只有一次 RTP 创建和一次 SIP INVITE 调用。
- `InviteStreamServiceImplTest.waiterRegistrationAndCompletionAreAtomic` 验证 100 个等待者与完成操作并发时，各收到一次结果。
- SIP 会话确认、媒体到达、数据库代次投影、下载结果保留及旧 owner 保护的定向测试通过。

这些是编排与回归测试，其中 owner 认领使用 mock CAS。真实 Redis 的 Lua 并发竞争、跨实例表现仍需集中执行集成测试，不能以本轮单元测试替代。

## 默认密码功能的实测问题

### 1. 单独提交缺少依赖，无法编译

在新基线源码副本应用 `e80b866d5` 后执行 Maven compile，报 `UserController` 找不到 `PasswordComplexityValidator`。补入 `8fe1d723a` 的该类后，795 个生产源码文件编译成功。仅确认编译通过，不表示整项功能可直接上线。

### 2. 通用 Mapper 更新会意外解除强制改密标记

上游在 `UserMapper.update()` 中无条件写入 `default_password=#{defaultPassword}`，而 `User.defaultPassword` 是默认 false 的 primitive boolean。

本轮用实际 UserMapper、MyBatis 及内存 H2 复现：数据库用户原标记为 true，仅创建包含 id/username 的部分 User 对象更新，未修改密码，标记就被清为 false。

这是拟合入补丁的 Mapper 层隐患；本轮没有证明存在可由外部请求直接利用的通用更新入口。适配时应把标记变更限定在明确的密码业务命令，或者使用可区分“未提供”和 false 的更新字段，并补回归测试。

### 3. 前后端密码规则不一致

新强制改密页允许双引号作为唯一特殊字符，但补缺提交的 Java 校验器未包含双引号。

以测试字符串 `Abcdefg12"`、用户名 `operator` 复现：Node 执行实际 Vue 文件中的正则返回 true，Java 实际校验器返回 false。页面允许提交，后端拒绝。应统一全部改密/新增用户页面和后端的规则。

### 4. 必须提供存量数据库升级方案

- 拟合入的新 Mapper 会使用 `default_password`，旧 schema 不升级会出 SQL 错误；已用内存 H2 删除该列后复现。
- 上游提供 MySQL 和 PostgreSQL/KingBase 的更新片段，且仅标记仍使用默认 admin 密码的 admin 用户，不是要求所有现存用户重置密码。
- H2 的该提交只修改初始化 schema/data，没有补充已有 H2 数据库的 default_password 升级脚本。
- 不得用重新执行初始化 SQL 代替增量迁移，避免覆盖用户及其他业务数据；也不要盲目重跑包含历史结构变更的整份更新 SQL。

### 已通过的局部检查

补齐依赖后的实际 JwtAuthenticationFilter 配合 mock JWT/IUserService 验证：默认密码用户访问普通业务接口返回 403；修改密码、退出接口放行；非默认密码用户访问普通业务接口放行。MyBatis 下划线字段映射能正确读出 true。

未启动完整安全过滤链、未构建 Vue 前端或进行浏览器端到端验证；仅测试局部放行不代表登录、登出、API Key 和旧 token 生命周期均已验收。
