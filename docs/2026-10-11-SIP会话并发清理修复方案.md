# SIP 会话并发清理修复方案

## 范围

按已确认的故障链路修复会话存储层：并发删除不应因其他 Call-ID 修改共享 EXPIRE ZSET 而冲突；事务失败不能静默；需要独立于设备离线的删除补偿。保留现有 V2/旧 Hash 迁移规则、owner 保护、TTL 和设备索引，不修改运行服务、不扩大压测、不提交既有工具改动或用户文件。

## 实施步骤与检查点

1. 添加回归测试，先验证共享索引 WATCH、失败静默和事务状态未释放能够被测试检出。
2. 删除、续期和过期扫描只监视本会话 DATA、STREAM、必要 META；仍将共享 ZSET 的写入与会话索引修改放在同一事务。过期扫描依赖续期同步更新 DATA/META 来保护 deadline，并重新检查主记录的 expireAt。
3. 区分事务提交成功、WATCH 冲突和异常；有命令的 EXEC 返回 null/空数组视为冲突。有限重试后输出操作及 Call-ID，删除方法返回明确的 boolean 结果。异常和提前返回都恢复当前连接的 MULTI/WATCH 状态。
4. 失败删除登记到独立 Redis ZSET（Call-ID -> 下一次重试时间），成功删除时在同一事务移除补偿记录。定时任务有批量和耗时上限，失败退避，不延长活跃会话 TTL，不降低清理验收标准。
5. 测试并发独立会话、替换 owner、重试耗尽、连接恢复、续期与过期竞态、补偿成功和失败路径。编译产物与测试依赖放在仓库内独立验证目录，不覆盖正在运行的包或已有 target/classes。

## 安全与验证边界

Call-ID 视为 SIP Dialog 的唯一身份。补偿只删除该 Call-ID；STREAM owner 已切换时保留新 owner。Redis 不可用时可能连补偿登记也失败，此时必须显式报错，不声称具备 Redis 故障期间的落盘保障。补偿记录不使用短 TTL，避免未处理意图自行消失；通过成功删除/确认已不存在后清掉。

修复后仍需安排真实环境验收：部署明确版本的候选包，至少三轮 10 路集中退出、并发平台停止、媒体离开/BYE 交错，均须在原 30 秒窗口内会话、流和 listener 归零，不得依靠设备离线兜底。运行包版本与当前源码不同，本次代码回归不能代替部署后的验收。

## 实施结果

### 代码变更

- `SipInviteSessionManager`：删除、续期、过期清理不再 WATCH 全局 EXPIRE，索引修改仍在同一个 MULTI/EXEC 中完成；过期清理检查 DATA 的 expireAt，并在每次重试重置过期判断。
- 事务提交：null/空 EXEC 都重试，命令结果中含异常也视为失败；最多三次尝试，耗尽记录操作、Call-ID、次数和异常。在同一绑定连接中执行 DISCARD/UNWATCH，覆盖异常和提前返回。
- 删除结果：`removeByCallId`、`removeByStream`、`removeByStreamIfSsrc` 返回 boolean；true 表示完成或按身份保护规则无需操作，false 表示未完成。调用方可继续忽略返回值，但失败已由管理器告警和登记补偿，不再静默。
- 调用链检查发现 `SIPCommander.streamByeCmd()` 在会话删除之后才发送 BYE，因此不新增“重试耗尽即抛异常”的行为，避免一次 Redis 冲突阻断后续 BYE、RTP 或其他业务清理。返回类型变更要求全量编译部署，不能只热替换管理器 class。
- `removeByCallId` 不再为终止中的会话续期；查询异常时也尝试登记已知 Call-ID。DATA 已丢失时使用 META 清理反向索引；Call-ID 不一致的异常记录保留并告警，不算补偿成功。
- 新增 `VMP_SIP_INVITE_SESSION_V2:PENDING_DELETE:<serverId>` ZSET，member 是 Call-ID，score 是下次尝试时间。成功删除时原子移除补偿；失败退避 5 秒。该记录不设 TTL，可跨 WVP 重启保留；不承诺 Redis 故障期间登记成功，也不替代 Redis 自身持久化配置。
- `SipInviteSessionCleanupTask` 每秒检查到期补偿，每批最多 100 条，执行间检查 500ms 耗时预算，第一次失败结束本批。该预算不抢占正在进行的 Redis 请求，单次请求仍受 Redis 客户端超时控制。

### 实际验证结果

1. 修改前的独立验证器检出共享 EXPIRE WATCH、重试耗尽静默、空 EXEC 当成功、WATCH 状态未释放四类问题；新增终止删除续期、查询失败未登记意图、异常记录误算成功三个用例也先失败，再修改代码转绿。
2. 使用仓库内旧包的生产依赖（Spring Data Redis 3.4.4、Lettuce 6.4.2 等）独立编译全部 785 个生产 Java 源文件：通过，仅有既有弃用/unchecked 提示。输出在 `target/session-cleanup-check/full-classes`，未覆盖已有 `target/classes` 或运行包。
3. 调用实际修复后的管理器，以每线程独立连接、WATCH 版本校验、排队 MULTI 和原子 EXEC 模拟 Redis 事务，独立验证 **23/23 通过**。覆盖不同 Call-ID 双线程同时删除、同一 Call-ID 重复删除、续期插入过期事务提交前、补偿退避、owner 保护、批量和耗时预算等。注入失败时出现 WARN/ERROR 是预期现象，不是测试失败。
4. 验证器保留在 `src/test/java/com/genersoft/iot/vmp/gb28181/session/SipInviteSessionConcurrencyVerifier.java`，JUnit 入口及接口行为用例在相邻 `SipInviteSessionTransactionsTest.java`。本轮 JUnit/Mockito 依赖下载网络超时，**未运行 Maven/JUnit 测试套件**；独立验证不是实际 Redis 集成测试。
5. 未部署、未重启 WVP/ZLM，未操作真实摄像头，未进行修复包的真实环境验收；既有工具改动、配置、报告、抓包均保留。
