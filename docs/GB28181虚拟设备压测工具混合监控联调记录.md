# GB28181 虚拟设备压测工具混合监控联调记录

## 环境要求

- WVP HTTP 控制接口可访问，通常为 `18080`。
- WVP SIP UDP/TCP 端口和 RTP 端口范围可访问。
- ZLMediaKit HTTP API 可访问，通常为 `19001`，并确认 `getMediaList` 权限和 secret。
- Prometheus 可访问 `/api/v1/query_range`。
- WVP、ZLM、Redis、MySQL、主机 exporter 已配置为 Prometheus targets；不同部署的指标名通过 `monitoring.prometheus.queries` 覆盖。

## 测试命令

```bash
cd tools/gb28181-load-test
GB28181_LOADTEST_INTEGRATION=1 \
  ./scripts/run-integration.sh configs/test-10.yaml
```

启用监控时在配置中增加：

```yaml
monitoring:
  enabled: true
  sampleInterval: 15s
  prometheus:
    url: http://127.0.0.1:9090
  zlm:
    enabled: true
    url: http://127.0.0.1:19001
    mediaServerId: zlmediakit-local
```

## 验收内容

检查以下文件：

- `reports/run.json`：判定、业务摘要、资源摘要和 ZLM 残留资源；
- `reports/run.csv`：阶段汇总；
- `reports/run.details.csv`：设备和点播明细；
- `reports/run.resources.csv`：Prometheus/ZLM 原始采样；
- `reports/run.md`：人工审阅报告。

同时检查压测工具 `/metrics` 和 WVP/ZLM 日志，确认点播成功、媒体到达、停止清理和 ZLM 流注销时间一致。

## 风险与限制

- 当前工具不会自动部署 exporter；缺少 Prometheus 或 exporter 时报告应为 `INCONCLUSIVE`，不能解释为资源为零。
- ZLM API 只反映查询瞬间的流列表；最终残留流检查依赖测试结束后 ZLM 仍可访问。
- 指标名和标签由部署决定，默认 PromQL 仅适用于常见 Spring Boot、node_exporter、redis_exporter 和 mysqld_exporter 配置。
- 单次测试只能判断当前负载是否满足 SLO，必须执行多个阶梯负载才能确认稳定容量。
- 报告不会保存密码、控制 token、ZLM secret 或 SIP Authorization。
